## 3. 質問2 — 検索の番号は商品ページの表示と一致する

判定規則は**要素`[data-testid="商品の状態"]`の1行目と、master表が与える表示名との厳密比較**。
包含一致は別に数え、一致率へ入れない。要素が読めなければ**比較不能**として率から外す。

| 指標 | 第2回 |
|---|---:|
| 標本 | 20件 |
| 要素を読めた商品ページ | **20 / 20** |
| 比較できた | 20件 |
| **厳密一致** | **20件（100%）** |
| 包含（一致に数えない） | 0件 |
| 不一致 | 0件 |
| **比較不能** | **0件** |

| 番号 | 標本 | 厳密一致 |
|---:|---:|---:|
| 1 新品、未使用 | 4 | 4 |
| 2 未使用に近い | 4 | 4 |
| 3 目立った傷や汚れなし | 4 | 4 |
| 4 やや傷や汚れあり | 4 | 4 |
| 5 傷や汚れあり | 4 | 4 |
| **6 全体的に状態が悪い** | **0** | **—（未観測）** |

標本は番号ごとに巡回して選んだ。先頭から20件取ると、母集団で最も多い番号3に偏り、
**1つの番号についての率を表全体の率として読む**ことになる。

### 商品ページ側の表示

要素は2行を持つ。1行目が状態の名前、2行目はMercari自身の説明文である。

```text
新品、未使用
新品で購入し、一度も使用していない
```

**照合したのは1行目だけである。** 2行目は説明であり、Card Diggerは表示しない。

## 4. 1回目の判定規則は間違っていた

**1回目は要素のテキスト全体を表示名と比較し、20 / 20が`contains`（包含）になった。**
不一致0・比較不能0だが、**厳密一致も0**である。

原因は、要素が名前だけを持つと決めてかかったことにある。2行構造をDOMで確かめていなかった。

| | 1回目 | 2回目 |
|---|---|---|
| 比較相手 | 要素のテキスト全体 | **要素の1行目** |
| 厳密一致 | 0 / 20 | **20 / 20** |
| 包含 | **20 / 20** | 0 |

**包含を一致率へ繰り上げて解決しなかった。** それは価格で一度やった失敗そのものであり
（[検証の落とし穴](../../docs/retrospectives/2026-09-01-verification-pitfalls.md)）、
`contains`という区分は元々そのために置いてある。直したのは**比較相手**であって規則ではない。

**1回目のartifactは2回目の実行で上書きされた。** 既定の出力先が同じであるため
（[Test運用規約 §9](../../docs/development/test-policy.md#率を記録するときの規約2026-09-01追加)の
6番「生の実測値を残す」に対する取りこぼし）。繰り返し実行するときは`--output`を分けること。
