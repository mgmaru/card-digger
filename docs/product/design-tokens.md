# 視覚方針 — 色・書体・余白

## 文書ステータス

- 作成日: **2026-09-02**
- ステータス: **未決。この文書は決めるべきことの一覧である**
- 対象: 色、書体、Type scale、余白、Badgeの表現、品質下限
- 前提: [MVP実装仕様](mvp-spec.md) / [アーキテクチャと用語](../development/architecture.md)

**まだ何も決まっていない。** [MVP仕様 §2.2](mvp-spec.md#frontend-styling2026-09-02決定)がCSS Modulesを
選んだところで止まっており、**そのCSSへ何を書くかは未決**である。

## 1. この文書がある理由

**見た目の決定を引き受ける文書が無かった。** 既存の3文書はそれぞれ別のものを引き受けている。

| 文書 | 引き受けているもの |
|---|---|
| [MVP仕様](mvp-spec.md) | 機能、画面挙動、画面に出す文言、完了条件 |
| [アーキテクチャ](../development/architecture.md) | 層、依存の向き、固有語 |
| [CIとMerge基準](../development/ci-policy.md) | Job、Merge、Branch |
| **この文書** | **色、書体、余白、Badgeの見え方** |

**1-1（検索UI）の下に置かなかったのは、1-2と1-3も同じ色と書体を使うからである。** 画面ごとに
決めると、2つ目の画面へ着手するときに「決め直すのか」が分からなくなる。

## 2. 決めること

### 2.1 色

- [ ] 基本の4〜6色を名前付きのhex値で定める
- [ ] **`partial=true`の警告色を定める** — [MVP仕様 §5.4](mvp-spec.md#54-検索結果metadata)は
  「警告色を使用し」としか書いておらず、**実体が無い**
- [ ] Contrast比を満たすことを確認する（§3.3の品質下限）

### 2.2 書体

- [ ] 書体を1つ、または明確に異なる2つ選ぶ
- [ ] Type scaleを定める
- [ ] **日本語で成立することを確認する。** 画面の文言は全て日本語であり、
  欧文用の指針をそのまま当てられない

### 2.3 余白とLayout

- [ ] 余白の段階を定める
- [ ] 商品Card Gridの列数がMobile / Desktopでどう変わるかを定める

### 2.4 Badgeの表現

[MVP仕様 §5.6](mvp-spec.md#56-商品card)の3種を、見た目で区別する。

- [ ] `通常出品`
- [ ] `オークション`
- [ ] `形式不明`

**`形式不明`を`通常出品`に見えるようにしてはならない。** 進行中の入札を、そのまま払える価格の
隣に並べることになる（[アーキテクチャ §5.3](../development/architecture.md#53-一般名を持たない固有語)の
`SaleFormat.UNKNOWN`の扱いと同じ理由）。

### 2.5 品質下限

[MVP仕様 §3.3](mvp-spec.md#33-共通ui)が要求している。

- [ ] Keyboard focusが見えること
- [ ] `prefers-reduced-motion`を尊重すること
- [ ] Mobile / Desktopの両方で使えること

## 3. 決めるときの制約

### 3.1 文言は決め直さない

**この文書は見た目だけを引き受ける。** 画面に出す日本語はMVP仕様が確定させており、
そちらが正本である。

| 確定済み | 場所 |
|---|---|
| 取得範囲・停止理由の表示 | [§5.4](mvp-spec.md#54-検索結果metadata) |
| 掲載日と更新日時の断り書き | [§5.6](mvp-spec.md#56-商品card) |
| Seller取得上限の表記 | [§6.3](mvp-spec.md#63-取得上限の表記) |
| Seller Knowledgeの表示 | [§7.7](mvp-spec.md#77-表示内容) |

`.claude/skills/frontend-design`を使うときの境界も同じで、
[そのREADME](../../.claude/skills/frontend-design/README.md)に書いてある。

### 3.2 依存を増やさない

[MVP仕様 §2.2](mvp-spec.md#frontend-styling2026-09-02決定)がCSS Modulesを選んでいる。
Component Libraryも Icon Setも Web Fontの読み込みも、入れるならPackage表の更新と
選定理由が要る。

### 3.3 この製品は情報密度の高い道具である

Landing pageではない。**取得範囲・停止理由・限界の断り書きが常に画面に出ている**設計で、
それらを目立たなくする方向の判断は、[MVP完了条件](mvp-spec.md#mvp完了条件)の
「Mercari全体だと誤認させる表示がない」に反する。
