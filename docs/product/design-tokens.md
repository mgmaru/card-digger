Landing pageではない。**取得範囲・停止理由・限界の断り書きが常に画面に出ている**設計であり、

画面の文言はすべて日本語である。欧文向けの行長・行間・字面の指針をそのまま当てられない。

### 2.5 `形式不明`を`通常出品`に見せない


**`形式不明`が`通常出品`に見えると、進行中の入札を、そのまま払える価格の隣に並べることになる。**
[アーキテクチャ §5.3](../development/architecture.md#53-一般名を持たない固有語)の
`SaleFormat.UNKNOWN`を`FIXED_PRICE`へ畳まない理由と同じである。

[MVP仕様 §3.3](mvp-spec.md#33-共通ui)が要求している。Keyboard focusが見えること、
`prefers-reduced-motion`を尊重すること、Mobile / Desktopの両方で使えること。

**この文書が決めたことの大半は、成立しているかを目でしか見られない。**
見方は[Test運用規約 §12](../development/test-policy.md#layoutを目視で確認するとき)が持つ。
**値と理由はこちら、手順はあちら**である。

## 3. 決めた値

値だけでなく、**選んだ理由**を必ず添える。理由の無い値は、次に迷ったときに守れない。

### 3.1 出発点 ―― 主役は商品画像であって、画面ではない

この道具の仕事は[画像による一次選別](concept.md)であり、画面に並ぶのは
**室内照明で撮られた、白バランスの揃わない素人写真**である。段ボール、畳、木の机、
カーペット。**ほぼ例外なく暖色に寄っている。**

だから**地を暖色にしない。** cream系の地は暖色の写真と混ざり、写真が地に沈む。
寒色の灰を地にすると、同じ写真が前へ出る。§2.3が言う「情報密度の高い道具」は、
まず**写真が見えること**から始まる。

### 3.2 基本の色

| 変数 | 値 | 地に対するcontrast | 選んだ理由 |
|---|---|---|---|
| `--ground` | `#DCE0DF` | ― | 地。寒色の灰緑。§3.1のとおり暖色の商品画像を前へ出すため |
| `--sheet` | `#F2F4F3` | 1.2:1 | 入力欄と画像の下地。**操作できる面**と地を分ける |
| `--ink` | `#191F1E` | **12.6:1** | 本文。地の寒色を僅かに含ませる。純黒は灰緑の地の上で硬い |
| `--ink-quiet` | `#4F5A58` | **5.4:1** | 補足と日付。**断り書きもここに入る**ので、薄い灰にはできない |
| `--shu` | `#A13617` | **5.2:1** | 朱。用途は§3.3の1つだけ |
| `--rule` | `#B2BAB8` | 1.5:1 | 節を分ける罫。**これに依存する情報を持たせない**ので低くてよい |

**6色に収めた。** 販売形式3種を色で分けようとすると足りなくなるが、
§3.5のとおり**色ではなく塗りと地紋で分けた**ので増やす必要が無かった。

### 3.3 朱は1つの意味しか持たない ―― `partial=true`の警告色

[§5.4](mvp-spec.md#54-検索結果metadata)は「警告色」としか書いていない。**`--shu`を当てる。**

赤にしたのは一般的なError色だからではない。**朱は訂正と押印の色**であり、
「刷られた本文の脇に、後から書き込まれた注記」を指す。この製品が画面に出し続けるのは
まさにそれ ―― **Mercariの出品情報の脇に、Card Diggerが自分の限界を書き足したもの**である。

そこで朱の用途を次に固定した。**これ以外に朱を使わない。**

| 使う | 形 |
|---|---|
| 取得範囲・限界の断り書き（§5.4、§6.3、§7.7） | **左の縦罫だけを朱にし、文字は`--ink`で書く** |
| `partial=true` | 見出し「一部の結果だけを表示中」の**文字を朱**にし、節の上辺を朱の罫にする |
| `形式不明`Badge | 文字・枠・地紋を朱にする（§3.5） |

**朱で書くのは`partial=true`の見出しだけ。** 断り書きは常時画面に出続けるため、
段落単位で赤くすると注記ではなくError画面に見え、§2.3が要求する常時表示と両立しない。
**印は朱、文は墨。**

`#D97757`付近の暖かいterracottaは避けた。生成物に頻出する色で、朱の由来とも関係が無い。

### 3.4 書体 ―― 明朝とゴシックを役割で分ける

§2.2がWeb Fontの追加を禁じている。**単一利用者のLocal実行**なので、
手元に確実にあるSystem Fontから選べる。

| 変数 | 値 | 選んだ理由 |
|---|---|---|
| `--font-record` | `"Hiragino Mincho ProN", "Yu Mincho", YuMincho, serif` | **記録の声。**取得件数、Seller Knowledgeの数値、見出し |
| `--font-ui` | `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Yu Gothic", Meiryo, sans-serif` | **道具の声。**本文、Label、Button、Card |

**和文では明朝とゴシックの差が意味として読まれる。** 明朝は刷られた文書、ゴシックは標識と
画面である。この製品は「収集の記録」と「操作する道具」の2つを同じ画面へ載せるので、
その2つを書体で分けた。欧文向けのDisplay / Body という分け方より、**日本語の画面で強く効く。**

明朝は`--text-head`以上でだけ使う。小さい字の明朝は、環境によって線が痩せて読みにくい。

### 3.5 販売形式Badge ―― `形式不明`を`通常出品`に見せない

§2.5がこの画面でいちばん硬い制約を置いている。**色相・塗り・地紋の3つすべてを変えた。**
1つの手掛かりだけで分けると、色覚特性や印刷でその手掛かりが落ちたときに区別が消える。

| Badge | 文字 | 枠 | 地 | 意図 |
|---|---|---|---|---|
| `通常出品` | `--ink-quiet` | `--ink-quiet` 1px | 無し | **いちばん静か。**確定した事実で、注意を引く必要が無い |
| `オークション` | `--sheet` | `--ink` | **`--ink`で塗り潰す** | 価格が取得時点の暫定値なので、いちばん強い |
| `形式不明` | `--shu` | `--shu` 1px | **`--shu-hatch`の45°斜線** | 唯一の有彩色 + 唯一の地紋。**確認できなかったという印** |

地紋は`rgba(161, 54, 23, 0.08)`とした。**これ以上濃くすると、その上に載る朱の文字が
4.5:1を割る**（0.08で4.58:1、0.13で4.27:1）。角は丸めない（§3.7）。

### 3.6 Type scaleと余白

| 変数 | 値 | 選んだ理由 |
|---|---|---|
| `--text-note` | `13px` | 断り書き、Badge、Cardの日付。**これ以上小さくしない。**§2.3の断り書きは読ませるためにある |
| `--text-body` | `16px` | Browser既定。rootを縮めないので、利用者の文字サイズ設定と拡大が効く |
| `--text-sub` | `20px` | 小見出し |
| `--text-head` | `26px` | 見出し |
| `--text-record` | `40px` | 取得件数。ここだけ明朝の数字 |

すべて整数px。**CJKは字面が正方形で、小数pxだと縦と横の輪郭が同時に濁る。**

| 変数 | 値 | 選んだ理由 |
|---|---|---|
| `--leading-body` | `1.75` | **漢字は字面が密で、欧文の1.5では行の切れ目を掴みにくい** |
| `--leading-dense` | `1.6` | Card内の日付など、2〜3行で終わる塊 |
| `--tracking` | `0.02em` | 和文ゴシックは僅かに空けたほうが語の切れ目が見える |
| `--measure` | `38em` | **全角38字。**1emが全角1字なので、そのまま字数になる。欧文の80字はそのまま当てられない |

余白は`--space-1`から`--space-7`まで`4 / 8 / 12 / 16 / 24 / 32 / 48`px。
**本文16px × 行送り1.75 = 28pxの行箱を、4pxが7等分する。**縦のリズムを崩さない刻み。

### 3.7 Grid列数と角丸

`--grid-min: 200px`とし、`repeat(auto-fill, minmax(var(--grid-min), 1fr))`で並べる。
**列数ではなく画像の最小幅で決めた。** 200pxを下回ると、まとめ売りの写真が
「カードの山か、Binderか」を判別できず、一次選別が成立しない。

結果として 2列（〜490px） / 3列（〜720px） / 4列（〜940px） / 5列以上 と変わる。
**600px以下では`--grid-min: 150px`へ落とす。** 手に持つ画面は被写体が近く150pxでも判別でき、
1列にすると一次選別の速度が落ちる。**2列を下限とし、それ未満にはしない。**
狭い画面で変えるのは`--text-record` `--text-head` `--text-sub` `--grid-min`の4つだけで、
**色・書体・余白の段階は変えない。**変えると体系を2つ保守することになる。

`--radius: 3px`は**「操作できるもの」の印**として、入力欄とButtonにだけ使う。
**画像とBadgeは直角のまま。**写真は触る面ではなく見る対象であり、Badgeは状態の表示である。

### 3.8 未更新期間の棒

何を表すかは[MVP仕様 §5.6](mvp-spec.md#未更新期間の棒2026-09-02決定)が持つ。
ここが引き受けるのは**見え方と、その理由**である。

| 項目 | 値 | 選んだ理由 |
|---|---|---|
| 高さ | `4px` | Cardの下端に置く。文字1行より薄く、写真の邪魔をしない |
| 色 | `--ink` | **唯一の有彩色は朱で、朱は限界の注記に予約済み**（§3.3）。棒は事実であって注記ではない |
| 軌道 | **描かない** | 目盛はGrid上部に1つあれば足りる。Cardごとに灰色の帯を敷くと、短い棒の「見るものが無い」が伝わらなくなる |
| 右端 | `2px`の角丸。365日以上は直角 | 角丸は値の終わり、直角は**切り詰めた**印 |
| 左端 | 直角 | 起点であって値ではない |
| 最小幅 | `2px` | 1日でも0にしない。**空白と「未取得」を見分けられなくなる** |

**摘みを置かない。掴めるものを描かない。** 最初の試作は掲載日を丸い点、未更新期間を線で
描いていたが、**Sliderに見えて操作できると誤解された。** 点を外し、棒1本にした。

**CSS変数を足していない。** `4px`と`2px`はこの部品にしか出てこない寸法で、
[§3.6](#36-type-scaleと余白)の余白段階とも独立している。**1か所でしか使わない値を
変数にすると、変数表が「どこで使うか分からない値」で膨らむ。**
部品のCSS Moduleへ直接書く。

### 3.9 品質下限（§2.6）

- **Keyboard focus**: 墨の環（`2px`）と面の環（`box-shadow 0 0 0 2px`）の**二重**。
  墨だけでは、塗り潰した`オークション`Badgeやリンクの上で環が溶ける
- **`prefers-reduced-motion`**: `base.css`で`animation` / `transition` / `scroll-behavior`を止める。
  現時点で動きは足していないが、後から足したときに必ずここを通す
- **Contrast**: 本文12.6:1、補足5.4:1、朱5.2:1（地紋の上でも4.58:1）、反転文字15.1:1。
  **文字は全て4.5:1以上。** `--rule`だけが1.5:1だが、罫に依存する情報を持たせていない

値はCSS変数として`src/frontend/src/tokens.css`の1か所へ置く。
**この節と`tokens.css`は同じ変更で直す。**
